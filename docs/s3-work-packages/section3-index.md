# Section 3 \- Work Packages

Section 3 covers the Work Package (WP) itself \- the core unit of work in Agilic \- from first opening one, through creating and pre-planning it, to the full set of Planning, Settings, and Reporting tools available once it's under way.

## Contents of this Section:

* [**Navigate a Work Package**](https://agilic-wiki.local/s3-work-packages/navigate-a-work-package) \- A quick tour of everything you'll find once you open a Work Package. Start here.  
* [**Create a Work Package**](https://agilic-wiki.local/s3-work-packages/create-a-work-package) \- Walks through creating a new Work Package and getting people added to it \- something you'll do every time a new project or task needs its own dedicated space.  
* [**Things to Consider When Pre-Planning a Work Package**](https://agilic-wiki.local/s3-work-packages/things-to-consider-when-pre-planning-a-work-package) \- Everything you set up before you have your full team or are ready to plan the schedule: defining the Work Package itself, preparing your roster, and setting resource allocations.  
* [**Work Package Planning**](https://agilic-wiki.local/s3-work-packages/work-package-planning) \- Every Planning tool for organizing your schedule once your team is assembled: Task Relationships, PERT Chart, Gantt Chart, Work Breakdown Structure (WBS), and Baseline Planned.  
* [**Work Package Settings**](https://agilic-wiki.local/s3-work-packages/work-package-settings) \- WP-level configurations across the Work Package, Work Item Type, Item, Reporting, Labels, and Module Access sub-tabs.  
* [**Work Package Management**](https://agilic-wiki.local/s3-work-packages/work-package-management) \- The connector document for everything inside a Work Package \- ties together the areas that already have their own deep-dive guides and covers what doesn't have a dedicated home yet.  
* [**Work Package Client Portal Management**](https://agilic-wiki.local/s3-work-packages/work-package-client-portal-management) \- Only relevant if the Work Package has external clients. Controls exactly what a client can see \- which milestones, RIDE items, and status updates get shared with them.
