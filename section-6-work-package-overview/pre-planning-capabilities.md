## Defining the Work Package

Work Package Management includes several fields specifically for defining what the Work Package is meant to achieve, and what happens depending on whether it succeeds.

**Objective** — what this Work Package needs to achieve.

**In Scope** — what's explicitly included in this Work Package's work.

**Out of Scope** — what's explicitly excluded — just as important as what's in scope, since it sets expectations up front about what this WP will not cover.

**Value if Completed** — the value delivered if this Work Package is successfully completed.

**Impact if Not Done** — what happens if this Work Package doesn't get done — the cost of not doing this work.

## Preparing Your Roster

Before work starts, it helps to know not just who's doing the work, but what skillsets you'll need — even before you know exactly who will fill them.

**Role Placeholders** — from Roster → Add a Team Member, you can add a Role Placeholder instead of a specific person, for when you know what skillset you need but not yet who will be doing the work.

- Role Placeholders can be defined at the org level, available for any Work Package to use.
- Each Work Package can also add its own role placeholders as needed, for unique circumstances specific to that WP.

![Role Placeholders](media/06e-007.png)

> **See also:** Org-level Role Placeholders are managed in [Adding & Managing People](/section-3-recurring-admin-tasks/adding-managing-people.md) (Section 3). The underlying concept is also covered in [Permissions for People](/section-2-setting-up-your-org/permissions-for-people.md) (Section 2).

> **Tip:** Using Role Placeholders early lets you build out your WBS and schedule around the roles you'll need, even before recruiting or reassigning the actual people.
